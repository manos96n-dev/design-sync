# Design Sync quick start

Design Sync answers which selected design units are unmapped, match a previously accepted baseline, have design/code changes, or need review. It does not infer correctness from generated code.

## Install

Requires Node >=22.12.0 and a Node package manifest. Any framework—or none—is supported. Replace the URL with your hosted registry; this repository initially provides a static build only.

```sh
npx shadcn@latest add https://<registry>/r/design-sync.json
pnpm exec tsx tools/design-sync/cli.ts init --file YOUR_FILE_KEY --tracking-roots '0:1'
```

The initial direct command bootstraps missing package scripts. Existing conflicting scripts are preserved and reported. Use npm/yarn/bun equivalents if needed. In pnpm monorepos install at the repository root; if pnpm prevents root dependency additions, opt in using its documented `--ignore-workspace-root-check` configuration for that installation.

Set `FIGMA_ACCESS_TOKEN` securely in your shell or CI secret environment. The CLI does not automatically read `.env` files. No credentials belong in tracked state.

```sh
pnpm design:scan
pnpm design:register --node '123:456' --route '/example/[id]' --files 'app/example/[id]/page.tsx,src/components/example-view.tsx'
# Implement and verify the application before accepting its baseline:
pnpm design:sync --node '123:456'
pnpm design:status
pnpm --silent design:status --json
```

Page or section roots define discovery scope. Only outermost matching child units are discovered; their complete descendants participate in hashing. Include nested units explicitly when they are independently implemented.

## Ownership

| Location                   | Owner                           | Upgrade behavior                      |
| -------------------------- | ------------------------------- | ------------------------------------- |
| tools/design-sync/         | Registry                        | Review and replace source changes     |
| docs/design-sync/          | Registry                        | Replaced by reviewed registry updates |
| .design-sync/config.json   | Project                         | Preserved; explicit migrations        |
| .design-sync/manifest.json | Project                         | Preserved; explicit migrations        |
| .design-sync/snapshots/    | Project                         | Committed baseline data; preserved    |
| .design-sync/cache/        | Disposable project observations | Gitignored; regenerated by scan       |
| Dedicated agent skill/rule | Project after opt-in            | Never overwritten by init             |

Commit config, manifest, and snapshots together. Snapshots contain design text and properties: keep them in a repository with access appropriate for the design.

## Status example

```text
Design Sync

Design observation: 2025-01-01T00:00:00.000Z (cache, 30s old)

✓ Login
  IMPLEMENTED
  /login

△ Example screen
  DESIGN_CHANGED
  /example/[id]
  1 design changes

○ Waitlist
  NOT_IMPLEMENTED
  MAPPING_MISSING
```

`status` rehashes local files but does not contact Figma. Observation age always appears. `status --refresh`, `scan`, and `check` fetch designs. A missing or invalid cache requires a scan; there is no silent offline fallback in CI.

## Upgrade

1. Commit project state and local toolkit customizations.
2. Inspect `npx shadcn@latest add https://<registry>/r/design-sync.json --dry-run` and `--diff`.
3. Apply the reviewed tool update. Use `--overwrite` only when ready to replace registry-owned files.
4. Run `pnpm design:migrate` to preview supported state migrations; use `--apply` when needed. V1 has no prior production schema and rejects unknown versions.
5. Run a scan and inspect status. Normalization incompatibility requires review; it never silently accepts a new baseline.

Use immutable versioned registry URLs for reproducible upgrades. A registry item carries a tool version in metadata; shadcn distribution is source replacement, not a toolkit package lifecycle manager.
